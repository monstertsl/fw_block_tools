# 设备联调工具（Windows 独立运行）

与奇安信(qianixn)、深信服(sangfor)、天融信(topsec)等防火墙的对接：登录、查询、封禁、解封、批量导入封禁。
**零第三方依赖**（网络 `urllib`、界面 `tkinter`、表格解析 `zipfile`/`xml`、天融信口令加密为内置 AES 实现），
Windows 官方 Python 装好即可运行，不用 `pip install`。

## 目录结构

```
fw_block_tools/
├── kit/                     # 共享包（协议客户端 + 通用界面 + 表格解析 + 日志）
│   ├── common.py            # 错误类型、IP 校验与提取、xlsx/csv 解析、日志脱敏
│   ├── secret_store.py      # 连接配置加密保存（ctypes 调 Windows DPAPI）
│   ├── ui.py                # 通用 GUI 骨架（DriverSpec 驱动）、日志出口
│   ├── registry.py          # 设备清单：统一入口与各设备入口的唯一来源
│   └── drivers/
│       ├── sangfor.py       # 深信服 AF
│       ├── qianxin.py       # 奇安信防火墙
│       ├── topsec.py        # 天融信防火墙（含纯 Python AES-128）
│       ├── nsfocus.py       # 绿盟 NF 防火墙
│       └── hillstone.py     # 山石网科防火墙（地址簿组封禁）
├── device_tool.py           # 统一入口（默认深信服，窗口内切换）
├── run.cmd                  # 双击启动 device_tool.py
├── device/                  # 各设备单独入口（默认选中对应设备）
│   ├── sangfor_af_tool.py
│   ├── qianxin_fw_tool.py
│   ├── nsfocus_nf_tool.py
│   ├── hillstone_fw_tool.py
│   └── topsec_fw_tool.py
├── README.md
└── logs/                    # 日志输出目录，首次真实操作时自动创建
```

勾选「保存密码」产生的凭据**不放在工具目录**，而是落到用户目录（见下节），
所以整个 `fw_block_tools` 目录可以直接拷给别人，不会带走任何密文。

厂商差异（标题、默认地址、额外字段、是否支持列表）集中在 `kit/registry.py`，`device/` 下的入口脚本只有几行，
调用 `run_tool` 拉起同一套界面。**拷贝整个 `fw_block_tools` 目录**即可在别的机器运行，入口按相对路径导入上一级的 `kit`。

## 运行

双击 `run.cmd` 即可，**不会弹出控制台窗口**（内部用 `pyw -3` / `pythonw` 启动，cmd 窗口随即关闭）。

需要在命令行里看输出时用控制台模式：

```bat
run.cmd console
```

也可以命令行直接跑 `python device_tool.py`（会附带一个控制台窗口）。
`run.cmd` 会先切到脚本所在目录；找不到 `pythonw` 时自动退回控制台模式。
无窗口启动时若初始化失败，会弹窗提示，并把完整堆栈写到 `logs/startup_error.log`。

## 统一入口

窗口最上方是「设备类型」下拉框，选中哪个设备就按它的默认地址、额外字段、黑名单表格与日志文件渲染界面；
**界面只有一套**，切换设备不新开窗口。切换时：当前会话后台登出 → 清空界面填入新设备默认值 → 日志改指向新设备的 `logs/*.log`（该设备首次真实操作时才落盘）。
上一个操作（查询/封禁/批量）未结束时不允许切换，会提示稍候。

`device/` 下的入口用法相同，只是打开时默认选中对应设备：

```bat
python device/sangfor_af_tool.py
python device/qianxin_fw_tool.py
python device/topsec_fw_tool.py
python device/nsfocus_nf_tool.py
python device/hillstone_fw_tool.py
```

新增设备：在 `kit/registry.py` 的 `DEVICES` 里登记一条 `DeviceEntry`（显示名 + `DriverSpec` + 客户端类），
统一入口和各分入口都会自动出现该选项。

## 共同功能

| 区域 | 说明 |
|---|---|
| 设备连接 | 管理地址（只填 IP 时按 `https://` 补全）、用户名、密码、超时、是否校验 TLS（自签证书必须不勾） |
| 保存密码 | 勾选后把地址、用户名、密码等加密存到本机，下次启动自动填入；取消勾选即删除 |
| 单 IP 操作 | 查询状态、封禁、解封；先查再操作，已封禁/不存在时自动跳过（幂等） |
| 批量导入 | 选 `.xlsx`/`.csv`/`.txt` → 提取 IPv4 → 批量封禁/解封，可设间隔、可中途停止、结束给汇总 |
| 日志 | 追加写入 **`fw_block_tools/logs/`** 下的 `*.log`（与从哪个入口启动无关）；**启动不建文件**——该设备第一次真实操作或报错时才创建，界面上的启动提示不落盘；界面单行超长会截断，文件保留全文 |

日志里每次请求都有：方法 + 完整 URL、请求体/表单（`password`/`token`/`secret` 打码）、
响应状态码与耗时、响应体，以及**判定过程**（为什么判「已封禁 / 不在黑名单 / 不符合条件」的实际字段取值）。
需要别人协助定位时，直接把 `logs/` 下对应的 `.log` 发出去。

## 保存密码

「设备连接」区勾选**保存密码**后，管理地址、用户名、密码、超时、TLS 开关与该设备的额外字段
（如深信服命名空间、绿盟/山石 API Token、山石地址簿组名）会一起加密写入**用户目录**：

```
%LOCALAPPDATA%\fw_block_tools\<设备类型>.secrets      # 例如 topsec_firewall.secrets
```

下次启动该设备时自动回填并保持勾选。

- 加密走 Windows 自带的 **DPAPI**（`ctypes` 调 `crypt32.CryptProtectData`），作用域是**本机 + 当前用户**：
  文件拷到别的机器、换用户登录、或把工具目录整个拷走都解不开；删掉文件即当没保存过。
- 放用户目录而不是工具目录，是为了和 DPAPI 的作用域对齐，同时保证工具目录可以直接分发给别人。
- 保存内容**不是只存第一次**，会随输入更新。触发时机：①勾选的那一刻存一次；②之后每次操作结束（查询/封禁/解封/批量，成功或失败都算）用当前输入框内容覆盖；③关闭窗口时再覆盖一次。取消勾选立即删除文件。
- 地址、用户名、密码任一为空时**不覆盖**已保存的配置（避免清空输入框就把密码抹掉），只在界面日志里提示一行。
- 一个设备类型一个文件，切换设备时各用各的，互不覆盖。
- 密码在界面上仍是掩码显示，日志里始终打码，落盘只有 DPAPI 密文。
- 非 Windows 系统没有 DPAPI，该勾选框会置灰，其余功能不受影响（配置目录退回 `~/.fw_block_tools/`）。

## 厂商差异

| 项 | 深信服 AF | 奇安信 | 天融信 | 绿盟 NF | 山石网科 |
|---|---|---|---|---|---|
| 额外配置 | 命名空间（默认 `@namespace`） | 无（需 RESTful API 账号） | 无（密码填明文，工具加密） | API Token（用户名/密码留空） | API Token 或用户名密码（二选一）+ 地址簿组名 |
| 黑名单落点 | `whiteblacklist`（永久封锁名单） | `threat_disposal` 人工处置项（处置中心） | `安全策略 → 黑白名单 → 静态黑名单`（接口两套自选：`blackWhite` / `blackListSpread` 五元组） | `globalWb/blist` 全局黑名单（`sourceIp`） | `addrbook` 地址簿组（需策略引用才阻断） |
| 描述字段 | 支持 | 不支持（人工处置项无 desc） | 不支持（条目无 desc） | 不支持（条目无 desc） | 不支持（主机对象无 desc） |
| 列表接口 | 未开放（设备侧条目可上万，全量拉取会卡死；按 IP 单查即可） | 未开放（分页参数需真机核验） | 未开放（搜索接口无稳定分页） | 支持（`size=-1` 全量） | 支持（读地址簿组） |
| 会话 | `token` 放 Cookie | `token` + `__s_sessionid__` Cookie | Cookie + `Referer` + 轮转 `token` + `codeRun` | 静态 `Authorization` 头，无登录会话 | `X-Auth-*` 头 + 同名 Cookie + `X-API-Language`；401/403 或 `loginError_100x` 自动重登；415 时改 `text/plain` 重试 |
| 判成功 | `code==0` 或 `message=="成功"` | `head.error_code` 为 0/空 | `result is True` | `status==2000`（int 或字符串） | 无 `success:false` + 回读组内命中 |

## 批量导入规则

- 扫描**所有工作表、所有单元格**，不要求 IP 在固定列；
- 正则捞 IPv4 再逐个校验，`999.1.1.1` 这类伪 IP 丢弃；`10.0.0.1/24` 取 `10.0.0.1`；
- 去重并按出现顺序保留；`.csv` 自动尝试 UTF-8 BOM / GBK / UTF-16；`.xls` 提示另存为 `.xlsx`；
- 批量期间逐条请求明细只写日志文件，界面只保留 `[i/N]` 结果与错误行，避免刷屏。

## 排错

| 现象 | 排查方向 |
|---|---|
| 登录被拒绝 / 401、403 | 账号权限；设备「管理主机」限制需把本机出口地址加入可信；奇安信需 RESTful API 账号 |
| SSL 握手失败 | 不要勾「校验 TLS 证书」；确认端口 |
| 深信服提示未登录 | 命名空间填错会登到别的虚拟系统，或会话被踢，点「测试连接」重建 |
| 天融信登录失败 | 确认是明文密码；登录优先 `restLogin`，接口不存在时自动回落到 `addNoCode`；建议在设备上关掉登录验证码（不同版本机制不同）；`codeRun` 相关错误通常是设备时间/协议版本不符 |
| 绿盟返回 401 / `Token 校验被拒绝` | API Token 过期或被吊销：Web 界面「系统管理 → API 管理」重新生成；确认管理地址带 API 端口（默认 8081） |
| 山石 401 / `unauthorized` | 会话头或 Cookie 缺失，或账号无地址簿权限；确认 `X-Auth-Token` 与 `token` Cookie 同时带上 |
| 山石封禁成功但流量不拦 | 地址簿组没有被安全策略引用；本工具只维护组内 IP，策略引用需在设备侧一次性配好 |
| 深信服提示「黑白名单\["x.x.x.x"\] 已存在」 | 该 IP 已经在设备**白名单**里（或黑名单条目被停用了），同一个 IP 只能有一条名单记录，所以加不进黑名单。工具不改你的配置：先在设备 `安全运营 → 黑白名单` 里移除这条白名单或改成黑名单，再下发封禁（设备侧也可用 `PATCH .../whiteblacklist/{url}` 转换，但原白名单条目会丢失） |
| 绿盟提示「复查黑名单未见该条目」 | 设备返回成功但未落库：看日志里 `configuration` 的响应 `message`，多为字段不合规（`objectType`/`type`）或黑名单功能未启用 |
| 封禁成功但流量未阻断 | 工具只写入黑名单对象，是否拦截取决于设备上的策略引用与生效范围 |
| 批量大量失败 | 先看设备侧总量（深信服地址黑名单上限 1000 条量级）；也可能是接口限速，调大「间隔(秒)」 |
| 需要协助定位 | 把 `logs/` 目录下对应的 `*.log` 发出来，里面已含请求、响应、耗时与判定过程 |
